# Conversion journal contract

This is a source-reviewed **provisional** development contract. No journal
profile is admitted for normal collection. Contract fixtures prove parsing,
normalization and accounting boundaries, never confidential-memory behavior.
The runtime producer, replay integration and CLI integration must use this
contract; their existence and admission are separate checks. Normal requests
for an unadmitted journal return collection-unavailable exit 3. There is no
public unsafe override. Existing ordinary capture behavior remains available.

## Source meaning and admission

The candidate [profile](../profiles/journal-candidates/linux-7.0.14-x86-journal-provisional.json)
is generated by `tools/emit-journal-contracts`. Its source is Linux stable
[v7.0.14 commit 458c6079fc1d41d564c37679c8ace02cd83ee817](https://github.com/gregkh/linux/tree/458c6079fc1d41d564c37679c8ace02cd83ee817).
`arch/x86/mm/pat/set_memory.c` and `arch/x86/include/asm/set_memory.h`
declare `int set_memory_{decrypted,encrypted}(unsigned long addr, int numpages)`.
On x86-64 the address argument is 64-bit kernel virtual, pages and result
are signed 32-bit integers. The address argument is never part of the wire.

Zero is native wrapper success; nonzero is native wrapper failure. Both are
request/result observations only. Negative pages remain signed native metadata;
requested pages/bytes become null with `invalid_native_pages`. Nonnegative
pages multiply by the source-profile page size 4096 with checked arithmetic.
This counts requested bytes, never effective bytes. The source can return zero
without conversion when memory encryption is absent, and errors do not prove
rollback. AMD prepare/finish operations provide no persistent physical identity.
Early/boot conversion, pre-attach requests, MMIO, kexec/accept paths and other
unobserved interfaces remain excluded.

The provisional profile deliberately has null config, BTF and object hashes.
Null is an unmet assumption, never a wildcard match. Admission requires exact
source/config/BTF/object bindings, BTF signature agreement, all four real hooks,
enabled SNP evidence, independent owned native tuples, window/loss checks and
caller measurements when requested. Kernel eligibility starts at 6.11; version
alone admits nothing. The upstream snapshot does not admit a distribution image.
Any kprobe alternative needs its own profile and equivalent evidence; no fallback
is implicit. The existing libbpf-mojo 0.2.3 tracing interface remains sufficient
for the selected fentry/fexit route; no dependency revision is implied here.

## Selection

`record --capability conversion-journal` and the equivalent live `top` request
select only the journal. They must work independently of attempt-hook admission.
Omitting capabilities keeps the ordinary attempt-only default. A list of ordinary
capabilities keeps implicit attempts; a mixed journal/ordinary list also requires
attempts. All explicitly requested channels must admit or the request returns 3;
there is no substitution. Duplicate or unknown capability IDs are usage errors.

`--journal-object PATH` selects the packaged journal object explicitly; absent
means normal object discovery. It requires the journal. `--journal-callers`
requires the journal and enables bounded caller processing; it is off by default.
`--device` is invalid with journal-only (exit 2). In mixed captures it filters
ordinary DMA metrics only; journal observations remain global. Help, doctor,
qualify, record and live top must expose the same selection/admission semantics.
The pure `select_journal` model freezes these rules for CLI integration.
`journal_admission` returns an exit code and fixed reason after checking the
requested channels against declared profile admission. A zero result means
`ready_for_attachment`, never actual attachment or platform qualification.
Provisional, unadmitted and unknown requested journal profiles return 3; an
unrequested channel cannot cause refusal. Other ordinary capabilities retain
their existing independent admission checks.

## Fixed wire

The journal has an independent wire version 1, magic `MVJR` (0x524a564d),
exactly 72 packed little-endian bytes. The bridge frame is separate. Decoders
must read bytes at these offsets, never cast an unaligned native struct.
The declarations live in `bpf/include/memveil_journal.h`, which includes the
unchanged shared `memveil_events.h`. Existing attempt/lifecycle/copy layouts
and object bytes are unchanged.

| Offset | Width | Field |
| --- | --- | --- |
| 0 | 4 | magic |
| 4 | 2 | wire version = 1 |
| 6 | 2 | kind = 1 (native wrapper result) |
| 8 | 2 | flags: bit 0 matched entry; every other bit zero |
| 10 | 2 | direction: 1 decrypt, 2 encrypt |
| 12 | 4 | CPU observed at exit |
| 16 | 8 | per-CPU transport sequence |
| 24 | 8 | exit monotonic nanoseconds |
| 32 | 8 | nonzero capture admission epoch |
| 40 | 8 | operation token; zero only for unmatched exit |
| 48 | 8 | entry monotonic nanoseconds; zero for unmatched exit |
| 56 | 4 | signed native requested pages |
| 60 | 4 | signed native result |
| 64 | 2 | caller status: 0 disabled, 1 resolved, 2 unresolved, 3 ambiguous, 4 truncated |
| 66 | 2 | caller class: 0 unavailable, 1 owned, 2 swiotlb, 3 direct_dma |
| 68 | 2 | finite label code 0..10, table below |
| 70 | 2 | reserved zero |

Matched results require a nonzero token and entry time <= exit time. Unmatched
results require zero token/entry. Epoch is always nonzero. CPU <= 1048575.
A resolved caller requires the matching class/label; all other statuses require
zero class/label. Reject bad length, magic, version, kind, flags, enum, reserved
bytes or contradictory fields before normalizing. Native result includes positive
nonzero failures, not only negative errno. Tokens and timestamps are unsigned.

## Tokens, bounded memory and window

Use a bounded ordinary hash map keyed by the current-task pointer,
`task_struct.start_boottime`, window epoch and nesting depth, not CPU: migration
cannot change membership. The pointer is internal BPF task identity, never a
conversion address, persistent ID or address hash. The 32-byte internal key is
separate from the 72-byte exported wire; its reserved word is always zero. No conversion address is needed to pair.

Pinned [sched.h](https://github.com/gregkh/linux/blob/458c6079fc1d41d564c37679c8ace02cd83ee817/include/linux/sched.h)
defines `start_boottime` as u64. The provisional profile binds its source hash
and requires `bpf_get_current_task_btf` plus an exact BTF/CO-RE bounded u64 read.
These are source/helper assumptions until actual load/read/attachment evidence.
A missing helper, field, failed read, identity mismatch or exhausted map refuses
pairing and records uncertainty. The pointer remains only in bounded BPF memory;
no task pointer or birth value enters the wire, capture, report, log or fixture.
Bare PID, pointer alone and birth time alone are insufficient. This key separates
task reuse but does not prove callback completeness.
The hard budget is 4096 outstanding operations across 4096 task stacks, maximum
nesting 8 per task. State is never silently evicted. These are explicit resource budgets, not kernel concurrency claims: 4096 operations avoid an unconditional 65536-entry table for low-rate wrapper calls, while eight tracked depths bound per-task recursion. Approximate map value storage is under 1 MiB before kernel map overhead; actual charged memory, saturation and usefulness remain measured gates. Each accepted entry gets a
monotonic session-local token in 1..18446744073709551614, never an address hash,
PID, allocation ID or reusable region generation. The final u64 value is reserved
for exhaustion detection. Wrapping is forbidden. A task-lifetime-safe key is required: neither bare PID reuse nor an arbitrary
address can identify a new task as an old pending operation. The exact transient
identity source and BTF layout must be bound in the profile before producer
admission. If that source is unreadable, do not pair. A task-exit cleanup or a
missing callback censors outstanding entries instead of reusing them for later
tasks.

Entry depth and admission are maintained independently from transport success.
Nested overflow marks the task stack poisoned until its observed nesting unwinds;
exits from the poisoned interval are unmatched. Map insertion failure similarly
cannot cause an exit to consume an older token. Missing callback/depth evidence
poisons that task and degrades correlation; no guessed pairing is permitted.
Token/map/nesting exhaustion is counted explicitly and makes affected quality
partial. The admission gate closes on token exhaustion. Store entry epoch, direction
and signed native page count with each token; typed fexit arguments must agree
on all three before a result can consume it. A mismatch poisons the task stack,
censors the old entry and leaves the result unmatched. Matching direction/pages
alone cannot detect a lost entry/exit pair with equal arguments. If missed
callback detection is unproved or unavailable, operation correlation remains
unknown even when a token matches; a declared profile capability cannot upgrade
that uncertainty. Typed fexit request/result evidence remains useful independently
of entry membership. Entry counts and result counts are alternative measurements,
not additive totals. A later reducer must
reject duplicate nonzero tokens within one epoch, including cross-direction
repeats; decrypt and encrypt are separate requests, never a paired lifetime.

Replay permits at most 65536 disjoint token intervals across phase-aware history,
independently of the 4096 active-operation producer cap. Contiguous IDs merge;
internal entry and exit sharing one token is valid, while repeated same-phase
results or foreign/reused capture epochs are invalid. This external 0.2.0 format
contains only the result phase, not standalone entry events. On replay tracking
exhaustion, stop with exit 2 and an explicit `journal_token_resource_limit` reason;
this is a resource refusal, not a claim that the bytes were corrupted. Never
forget history or silently accept potential duplicates. Producer saturation
remains partial evidence, a separate condition. The production reducer must
meet the 600000 contiguous-event / 60-second / 256 MiB reference target and
exercise sparse/high-u64 cases. The development fixture validator has a smaller
65536-token set and is not that production algorithm.

Attach both exits before both entries with admission closed. Start from empty
maps, check all attachments and persist the initial checkpoint before readiness.
Prepare a nonzero epoch without claiming admission. The first durable empty
checkpoint has `admission_start_ns=null`, `admission_end_ns=null` and both
`admission_start_reason` and `admission_end_reason` equal to `not_opened`.
Capture start is a separate observed capture clock, never a planned journal
admission time. No journal result may precede readiness in this initial state.
Open entry admission only after the checkpoint is durable and record its actual
start time. A live checkpoint then has a known start and null end with
`admission_end_reason=admission_open`. `observation_end_ns` names only the verified
prefix cut while `capture.finalized=false`, not settled terminal observation.
A known admission timestamp has a null reason. Unknown readiness uses null start
with `readiness_unproved`, never zero; it cannot admit matched results. Unknown
final closure uses null end with `close_unproved`. A finalized known window has
actual start/end with null reasons. `JournalWindow` validates these states and
result membership without turning a prefix cut into closure proof.
An exit without an admitted entry remains `unmatched_exit`, not an in-window
request, even if its exit falls in the observation window. Startup census and
pre-window state are unavailable. The task/depth key is transient and never
persisted. Default journal ring size is 8 MiB; the existing lifecycle/copy rings
remain 32 MiB. BPF map/ring memory is reported separately from the 256 MiB
reference userspace RSS budget. Caller stacks have a separate 4096-entry,
16-frame maximum store when enabled; no stack map/helper is used by default.

On stop, close entry admission and record `admission_end_ns`, keep exits attached
while draining admitted work, then record `observation_end_ns` and final counters.
The session window ends at observation end, not admission close; result timestamps
may fall during drain, but matched entries must be in the half-open admission
window. Keep entry bookkeeping during drain so a nested post-close call cannot
steal an admitted parent's exit. The bounded stop deadline is 5 seconds; it is
not proof of quiescence. Count surviving operations as censored, preserve counters
and degrade terminal quality on timeout, missing callbacks or failed final reads.

Counter meanings are explicit: `entries` counts observed gate-eligible entries
before token allocation; exhaustion counters are subsets, not additional
requests. `exits` counts typed exits in the observation epoch before transport;
`matched_results` and `unmatched_exits` partition their observed pairing result.
`censored` counts admitted operations known unresolved/poisoned at the terminal
cut; it is null when not observable, including a progressing open checkpoint.
`ring_drops` measures failed reservations, `invalid_records` rejected decoding,
and `missed_callbacks` only an independently observable callback-loss source.
A per-CPU wire sequence advances before each result's reservation attempt, so
loss can leave gaps; persisted session sequence advances only after successful
normalization/write. Sequence/counter exhaustion never wraps silently.

Counter snapshots are not atomic across CPUs. No global inflight value, quiet
ring, detached link or equal totals proves settled global membership. A producer
must name an independently justified synchronization proof before `closure=proved`;
the provisional profile has no such proof, so uses `unproved`. Native tuple
agreement in an owned serial oracle proves only that scenario. Detail, aggregate,
correlation, baseline and terminal quality stay independent. Per-CPU sequence gaps,
ring reserve failures, malformed records and missed callbacks are separate facts;
never add event detail to counters measuring those same requests. Every counter value is a canonical u64 string or null. The matching key in
`counter_reasons` is null for a measured value, otherwise `not_observable`,
`read_failed` or `overflow`. Missed callbacks without an observable counter are
null, never zero. Counter overflow must refuse exact totals, not wrap.
`closure_evidence` is null while unproved and otherwise names the exact
profile-bound synchronization evidence; authored text alone does not prove it. Default captures remain 60 s / 1 GiB.

## Caller classification and privacy

Only `--journal-callers` permits transient stack processing. Resolve at most
16 frames in memory, requiring exact source-backed symbol/module identity.
No addresses, raw frames, symbol offsets, task names, payloads or memory-content
hashes enter events, logs, debug output or ignored artifacts. A capture-file hash
is permitted. No arbitrary kernel page read or virtual-to-physical inference is
needed. Finite labels describe observed paths, not causal origin or a device.

| Code | Exact label | Class |
| --- | --- | --- |
| 1 | `mv_command_set [memveil_region_oracle]` | owned |
| 2 | `mv_restore [memveil_region_oracle]` | owned |
| 3 | `swiotlb_init_late` | swiotlb |
| 4 | `swiotlb_alloc_tlb` | swiotlb |
| 5 | `swiotlb_free_tlb` | swiotlb |
| 6 | `swiotlb_exit` | swiotlb |
| 7 | `dma_set_decrypted` | direct_dma |
| 8 | `dma_set_encrypted` | direct_dma |
| 9 | `dma_direct_alloc` | direct_dma |
| 10 | `dma_direct_free` | direct_dma |

Precedence: disabled first; any full 16-frame/truncated sample is truncated;
multiple matching classes or nonunique symbol/module resolution is ambiguous;
no uniquely allowed class is unresolved; exactly one class is resolved. Within
one class the lowest table code wins, making repeated frames deterministic.
Do not choose a class across conflicting matches. Module unload/reload uncertainty
is unresolved. The 95% unique-class target uses all entry samples as denominator;
no samples means unavailable. It is a live measurement gate, not a promise.

## External format and independent fixtures

Session/event/report `0.2.0` have separate new schemas. Existing `0.1.x` schemas
and fixtures remain unchanged and readable by the legacy reader. Current shipping
reader integration remains a separate implementation; unknown versions must
refuse rather than reinterpret data. Ordinary event kinds remain in mixed `0.2.0`
captures. The integrity `kinds` set is exactly the same ten event kind names,
including zero counts. No extra event kind is needed for censored operations:
those are explicit journal session counters, not fabricated native results.

`transition_result.data` contains direction/target, signed native requested pages,
nullable requested pages/bytes, page size, signed native result, epoch, nullable
operation token/entry time, membership, caller status/class/label, `region=null`,
`region_reason=request_only_source` and `effect=request_only`. It has no observer
context, address, range offset, allocation identity or inferred shared state.
All u64 values are canonical decimal strings, bounded by u64. Signed native ints
are JSON numbers. No persisted operation token is zero. Source correlation is
`direct` for admitted entry membership and `unpaired` for unmatched exits.

The report's journal summary separates requests, native successes/failures,
unmatched exits and censored calls. Nullable `censored` and `requested_bytes`
values have matching `censored_reason` and `requested_bytes_reason`; known
values carry null reasons. Only matched entries contribute to admitted
request totals. Requested bytes are summed without decrypt/encrypt netting and
become unavailable if any admitted size is invalid or the sum overflows.
`shared_bytes` and `unreverted_ranges` are always null with request-only reason.
`CONVERSION_FAILED` can describe a native failed request with state unknown.
Orphan encrypt, overlapping requests, unresolved callers and healthy persistent
allocation are informational, never generic leak findings. Controlled expected
reversion failures belong to the independent oracle assessment.

`tools/emit-journal-contracts` reproduces new schemas, the provisional profile and
synthetic success, failure, orphan encrypt, overlap, duplicate-token rejection,
pre-attach, unresolved/disabled caller, persistent, invalid-page, initial/open
checkpoint and censored-final cases. Checkpoint fixtures use `checkpoint.json`,
checkpoint-prefix integrity and expected recovery exit 4.
`tools/validate-journal-contracts` independently checks arithmetic, literal-byte
integrity, sequence/token uniqueness and request-only boundaries. The legacy
synthetic region tracker continues testing actual synthetic overlap/reuse/state
rules; these fixtures do not upgrade a production state capability. Future
lifetimes/census/exposure formats need separately versioned and admitted sources.
Do not loosen 0.2.0 to add state, peer identity or inferred allocations.

## Live harness manifests

The existing explicit arming flags remain. `MEMVEIL_CONFIDENTIAL_RANGE_MANIFEST`
is a new external input for `confidential-ranges` and `confidential-late-attach`;
`MEMVEIL_CONFIDENTIAL_GUEST_MANIFEST` is a new external input for
`confidential-real`. These are harness inputs only, never product environment
variables. The manifest contract is versioned `memveil-confidential-range/1` or
`memveil-confidential-guest/1`. Both bind candidate manifest SHA-256, target
profile ID, exact source/config/BTF, oracle source/module, ordinary transport
receipt, synthetic provenance and an exact required case ID set. Guest input
also binds the range manifest, enabled-SNP evidence, I/O receipt and tuple ledger
by SHA-256. File hashes identify evidence; they do not authenticate it.

| Suite | Exact required case IDs |
| --- | --- |
| confidential-ranges | owned-success, owned-retained, owned-restored, request-only-state, native-tuple-agreement |
| confidential-real | all range IDs plus enabled-snp, real-io, independent-tuples, loss-and-cleanup |
| confidential-late-attach | pre-window-absent, baseline-unknown, late-owned-tuples, request-only-state |

Armed harnesses call `validate_manifest(..., qualification=True)` to refuse
synthetic inputs; the default mode checks fixture structure only. Harnesses
must verify manifest bytes against the candidate loader, profile,
actual runtime evidence and independent ledger before reporting any positive
row. Reject absent/mismatched/duplicate cases, missing receipts, foreign profile,
synthetic input for real qualification, or a product rebuild fallback. Unarmed
returns 77. Armed missing prerequisites are a failure or explicitly NOT_RUN,
never PASS. A required positive product refusal is FAIL. Expected-negative rows
pass only with their declared boundary, exit, reason and cleanup independently
checked. These manifests freeze interfaces; actual live runner integration and
real SNP runs remain separate qualification work.
